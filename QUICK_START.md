# Инструкция по простому запуску

Эта инструкция — для тех, кто запускает инфраструктуру впервые и не обязан разбираться в Docker, Vault и Linux.
Всё расписано по шагам: какую команду, где и зачем набирать, что вы должны увидеть в ответ.

Если вы уже знакомы с проектом — короткая версия в [README.md](README.md).

## 1. Что это за проект, в двух словах

Этот репозиторий поднимает на сервере «инфраструктуру» — служебные программы, без которых не работают
наши сервисы (tf-auth, tf-bff, tf-funnel и сайт):

| Программа | Зачем |
|---|---|
| **PostgreSQL** | база данных |
| **Kafka** | передача потоков данных между сервисами |
| **RabbitMQ** | очередь команд и уведомлений |
| **Redis** | быстрое хранилище (кэш, ограничения попыток входа) |
| **nginx** | веб-сервер: принимает запросы из интернета, выдаёт сайт по `https://` |
| **Vault** | сейф для паролей. Все пароли лежат только в нём |

Всё запускается в **контейнерах Docker** — это как отдельные маленькие компьютеры внутри сервера.

Главная идея: **пароли нигде не записаны в файлах**. Они лежат в Vault, и программы забирают их оттуда сами.

## 2. Словарик

| Слово | Что значит |
|---|---|
| **Сервер** | удалённый компьютер с Linux, на котором всё работает |
| **Стенд** | один сервер со всем набором программ. У нас два стенда: **dev** (для разработки и проверки) и **prod** (боевой, для пользователей) |
| **Терминал** | окно, куда набирают команды текстом |
| **Команда** | строка текста, которую вводят в терминал и нажимают Enter |
| **Ветка** | версия кода в GitHub. Ветка `dev` выкатывается на стенд dev, ветка `prod` — на prod |
| **Выкатка** | обновление программ на сервере до новой версии из GitHub |
| **Vault запечатан (sealed)** | сейф закрыт: пароли внутри есть, но никто не может их прочитать. Так бывает после каждого перезапуска Vault |
| **Ключи распечатывания** | 3 длинные строки, которыми открывают Vault. Нужны любые 2 из 3 |
| **Root-токен** | «главный ключ» от Vault. Нужен только при настройке, потом его отзывают |
| **Личный токен** | ваш ключ от Vault для повседневной работы, строка вида `hvs.…` |
| **GitHub Actions** | автоматика GitHub: сама выкатывает изменения на сервер |
| **Runner** | программа на сервере, через которую GitHub Actions выполняет выкатку |

## 3. Что нужно заранее

Соберите это до начала — без любого пункта запуск остановится.

- [ ] **Сервер** с Linux (Ubuntu 22.04 или 24.04), минимум 4 ГБ памяти и 40 ГБ диска.
- [ ] **Адрес сервера** (IP, например `203.0.113.10`) и **имя пользователя** для входа (например `user1`).
- [ ] **Доступ по SSH**: пароль или SSH-ключ. Пользователь должен уметь выполнять `sudo`.
- [ ] **Домен** (например `greefob.ru` для dev, `thinkfaster.ru` для prod), и в DNS домена
      запись типа **A** указывает на IP сервера. Без этого не выпустится сертификат для `https://`.
- [ ] **Почта** для сертификата (на неё Let's Encrypt пишет, если сертификат скоро истекает).
- [ ] **Аккаунт GitHub** с правами администратора в репозитории `Think-Faster/think-infra`
      (и в репозиториях сервисов, если будете настраивать их доступ).
- [ ] **Менеджер паролей** команды (например KeePassXC или Bitwarden). Туда вы сохраните ключи Vault.
      ⚠️ Не в блокнот на рабочем столе, не в чат, не в скриншот.
- [ ] **30–40 минут** спокойного времени.

## 4. Как подключиться к серверу и набирать команды

### 4.1. Открыть терминал на своём компьютере

- **Windows 10/11**: нажмите `Win`, наберите `PowerShell`, нажмите Enter.
- **macOS**: Launchpad → «Терминал».
- **Linux**: `Ctrl+Alt+T`.

### 4.2. Подключиться к серверу

В терминале наберите (замените имя и адрес на свои):

```bash
ssh user1@203.0.113.10
```

- При первом подключении спросит `Are you sure you want to continue connecting (yes/no)?` — наберите `yes` и Enter.
- Если спросит `password:` — введите пароль. **Символы при вводе пароля не видны, так и должно быть.** Нажмите Enter.

Успех — вы видите строку вроде:

```
user1@vm-fd5448:~$
```

Это **приглашение сервера**: всё, что вы теперь набираете, выполняется на сервере.

### 4.3. Как вставлять команды

Команды из этой инструкции удобнее копировать, чем набирать:

| Где | Как вставить |
|---|---|
| PowerShell / Windows Terminal | правая кнопка мыши или `Ctrl+V` |
| PuTTY | правая кнопка мыши |
| Терминал Linux | `Ctrl+Shift+V` |
| Терминал macOS | `Cmd+V` |

Правила:

- Вставили команду → нажали **Enter** → дождались, пока снова появится приглашение `user1@…:~$`.
- Текст в угловых скобках `<вот такой>` — это **место для вашего значения**. Скобки `< >` не вводятся.
- Если команда «зависла» и ничего не происходит больше 10 минут — нажмите `Ctrl+C` и смотрите раздел 13.
- Отключиться от сервера: команда `exit`.

## 5. Подготовка сервера (один раз)

Все команды — на сервере (после `ssh`).

### 5.1. Установить Docker

```bash
curl -fsSL https://get.docker.com | sudo sh
```

Спросит пароль пользователя (символы не видны) — введите, Enter. Займёт 1–3 минуты.

### 5.2. Разрешить своему пользователю работать с Docker

```bash
sudo usermod -aG docker $USER
```

⚠️ Изменение вступает в силу **только после переподключения**. Выполните `exit`, затем снова `ssh user1@…` (шаг 4.2).

### 5.3. Установить git и openssl

```bash
sudo apt update && sudo apt install -y git openssl
```

### 5.4. Проверить

```bash
docker compose version
```

Ожидается строка `Docker Compose version v2.…`.

```bash
docker ps
```

Ожидается заголовок таблицы `CONTAINER ID   IMAGE …` (пустая таблица — это нормально).
Если вместо этого `permission denied` — вы не переподключились после шага 5.2.

## 6. Файл настроек стенда

У каждого стенда один файл с настройками (без паролей!):

- dev — [`stands/dev.env`](stands/dev.env)
- prod — [`stands/prod.env`](stands/prod.env)

### 6.1. Что в нём

| Строка | Что вписать | Пример |
|---|---|---|
| `TF_INFRA_DIR` | папка на сервере, куда ставятся программы. `~/` — ваш домашний каталог (прав sudo не нужно) | `~/tf.infra` или `/home/user1/tf/think-prod` |
| `DB_PORT` | порт базы данных на сервере. Не трогать | `5432` |
| `DOMAIN` | домен сайта, **без** `https://` и без `/` в конце | `greefob.ru` |
| `LETSENCRYPT_EMAIL` | почта для сертификата | `admin@example.com` |
| `DOCKER_NETWORK` | не трогать | `think-fast-net` |
| `FRONTEND_HOST`, `FRONTEND_PORT` | имя контейнера сайта и его порт | `tf-front`, `80` |
| `AUTH_HOST`, `AUTH_PORT` | имя контейнера tf-auth и его порт | `tf-auth`, `8081` |
| `BFF_HOST`, `BFF_PORT` | имя контейнера tf-bff и его порт | `tf-bff`, `8080` |

⚠️ **Паролей в этом файле быть не должно.** Если вписать туда пароль, выкатка остановится с ошибкой.

### 6.2. Как изменить файл (через сайт GitHub, проще всего)

1. Откройте репозиторий на github.com → нажмите на папку `stands` → на файл, например `dev.env`.
2. Справа вверху нажмите значок **карандаша** (Edit this file).
3. Исправьте нужные строки.
4. Нажмите зелёную кнопку **Commit changes…** → в окне оставьте «Commit directly to the `dev` branch»
   (или выберите нужную ветку) → **Commit changes**.

### 6.3. Проверить домен

На своём компьютере в терминале:

```bash
nslookup greefob.ru
```

В ответе в строке `Address:` должен быть IP вашего сервера. Если другой IP или ошибка — DNS ещё не настроен
(или не обновился — подождите до часа). Пока DNS не готов, запускайте с `--skip web-server` (шаг 8.2).

## 7. Скачать проект на сервер

Все команды — на сервере.

### 7.1. Скачать код

```bash
git clone https://github.com/Think-Faster/think-infra.git ~/tf/infra-src
```

Если репозиторий закрытый, git спросит:

- `Username:` — ваш логин GitHub;
- `Password:` — **не пароль от GitHub**, а **токен доступа**: github.com → аватар справа вверху →
  Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token →
  Repository access: `think-infra` → Permissions: Contents — Read-only → Generate. Скопируйте токен и вставьте.
  Символы при вставке не видны — это нормально.

### 7.2. Перейти в папку и выбрать ветку стенда

```bash
cd ~/tf/infra-src
```

Для dev:

```bash
git checkout dev
```

Для prod:

```bash
git checkout prod
```

### 7.3. Папка для программ

Если `TF_INFRA_DIR` в файле стенда начинается с `~/` (например `~/tf.infra`) — **ничего делать не нужно**,
скрипт создаст папку сам в вашем домашнем каталоге.

Только если там путь вне домашнего каталога (например `/opt/tf.infra`) — создайте её с правами администратора:

```bash
sudo mkdir -p /opt/tf.infra && sudo chown $USER /opt/tf.infra
```

## 8. Запуск всей инфраструктуры одной командой

### 8.1. Подготовьте менеджер паролей

Откройте его и создайте запись, например «Vault prod». Сейчас туда нужно будет вставить ключи.

### 8.2. Запустить

На сервере, в папке `~/tf/infra-src`:

```bash
scripts/bootstrap-stand.sh dev
```

Для prod — `scripts/bootstrap-stand.sh prod`.

Если DNS домена ещё не настроен (шаг 6.3), запускайте так — сайт поставите позже:

```bash
scripts/bootstrap-stand.sh dev --skip web-server
```

Скрипт идёт по 9 шагам, каждый начинается со строки вида `[STAND] 3/9 Vault` между линиями `=====`. Ниже — **что он спросит и что отвечать**.

### 8.3. Вопросы скрипта и ответы

**А. Ветка не совпадает со стендом** (только если вы не сделали шаг 7.2):

```
[STAND] WARNING: выкатывается ветка 'main', а стенд — 'dev'
Продолжить? [y/N]
```

Ответ: `n` и Enter, затем сделайте шаг 7.2 и запустите снова.

**Б. Ключи Vault — самый важный момент** (шаг 3/9, только при первом запуске):

```
################################################################################
#  Ключи Vault стенда dev. Показываются ОДИН раз и больше нигде не хранятся.
...
Unseal Key 1: 3kVq8mR2abcdEFGH...Zx0=
Unseal Key 2: Qp7Lw9a1abcdEFGH...Kd4=
Unseal Key 3: m2Xn5Tb8abcdEFGH...Hs1=

Initial Root Token: hvs.AbCdEf123456...
################################################################################
Введите 'saved', когда ключи сохранены:
```

1. Выделите мышью строки от `Unseal Key 1` до `Initial Root Token` и скопируйте
   (в PowerShell: выделить → Enter или правая кнопка; в Linux-терминале — `Ctrl+Shift+C`).
2. Вставьте в менеджер паролей. Проверьте, что вставились **все 4 строки целиком**.
3. Только после этого наберите `saved` и Enter. Экран очистится — ключи с него исчезнут.

⚠️ Эти ключи **нельзя восстановить**. Потеряете — пароли в Vault станет невозможно прочитать.

**В. Если Vault уже был запущен раньше** (повторный запуск скрипта):

```
Vault запечатан. Ключ распечатывания:
```

Вставьте `Unseal Key 1` (только значение после `Unseal Key 1: `), Enter. Символы не видны — это нормально.
Спросит ещё раз — вставьте `Unseal Key 2`.

```
Root-токен Vault:
```

Вставьте `Initial Root Token` (строка `hvs.…`), Enter. Если root-токен уже отозван — см. раздел 13, «Нужен root-токен».

**Г. Выкатка сервисов** (шаг 6/9) — вопросов нет, просто ждите 3–10 минут. Идут строки `[DEPLOY] …`,
в конце каждого сервиса — `Deploy <сервис> finished successfully.`

**Д. Доступ для GitHub** (шаг 8/9). Скрипт напечатает несколько блоков:

```
Добавить в GitHub: Settings → Environments → dev → Environment secrets

VAULT_ROLE_ID=1a2b3c4d-....
VAULT_SECRET_ID=5e6f7a8b-....

Добавить в GitHub репозитория tf-bff: Settings → Environments → dev → Environment secrets

VAULT_ROLE_ID=....
VAULT_SECRET_ID=....
```

(и так же для `tf-auth`, `tf-funnel`). Скопируйте **все блоки** в менеджер паролей, подписав, какой блок к какому
репозиторию относится. Они понадобятся в разделе 10.

**Е. Личный токен**:

```
Имя администратора для личного токена Vault (Enter — пропустить):
```

Наберите своё имя латиницей без пробелов, например `ivan`, Enter. Скрипт напечатает строку `hvs.…` —
это ваш **личный токен**. Сохраните его в менеджер паролей («Vault dev — токен ivan»).

**Ж. Root-токен**:

```
Отозвать root-токен сейчас? [y/N]
```

Если личный токен **сохранён** — `y` и Enter. Если сомневаетесь — `n` (отзовёте позже, раздел 12).

### 8.4. Успешное завершение

В конце будет:

```
================================================================================
Стенд dev развёрнут.
...
```

Если вместо этого строка `ERROR: …` — найдите текст ошибки в разделе 13. После исправления просто
**запустите ту же команду ещё раз**: уже сделанное скрипт пропустит.

## 9. Проверка, что всё работает

### 9.1. Контейнеры

```bash
docker ps --format 'table {{.Names}}\t{{.Status}}'
```

| Что видите | Что значит |
|---|---|
| `Up … (healthy)` | работает, всё хорошо |
| `Up … (health: starting)` | запускается, подождите минуту и проверьте снова |
| `Up … (unhealthy)` | запущен, но не отвечает — смотрите логи (раздел 12.5) |
| `Exited (0)` у `tf-kafka-init`, `tf-rabbit-init` | **нормально**: это одноразовые помощники, они сделали работу и завершились |
| `Restarting` или `Exited (1)` | ошибка — смотрите логи (раздел 12.5) |

Должны быть: `vault`, `tf-postgres`, `tf-redis`, `tf-kafka`, `tf-rabbit`, `tf-nginx` — все `Up`.

### 9.2. Сайт

Откройте в браузере `https://<ваш домен>`. Пока сервисы tf-front / tf-auth / tf-bff не выкачены,
сайт покажет **502 Bad Gateway** — это нормально: nginx работает, а сервисов за ним ещё нет.

### 9.3. Секреты

```bash
export VAULT_TOKEN='<ваш личный токен hvs.…>'
```

```bash
scripts/secrets.sh status
```

У всех строк в колонке `STATUS` должно быть `ok`.

## 10. Настройка GitHub (один раз)

Нужна, чтобы изменения из GitHub сами выкатывались на сервер.

### 10.1. Окружение (Environment) в репозитории инфраструктуры

1. github.com → репозиторий `think-infra` → вкладка **Settings** (шестерёнка вверху).
2. Слева **Environments** → кнопка **New environment**.
3. Name: `dev` (или `prod`) → **Configure environment**.
4. Блок **Deployment branches and tags**: выберите **Selected branches and tags** →
   **Add deployment branch or tag rule** → впишите `dev` (для prod — `prod`) → **Add rule**.
   ⚠️ Обязательно: без этого любая ветка сможет получить доступ к паролям стенда.
5. Блок **Environment secrets** → **Add environment secret**:
   - Name: `VAULT_ROLE_ID`, Value: значение из первого блока шага 8.3 Д (без `VAULT_ROLE_ID=`) → **Add secret**;
   - ещё раз **Add environment secret**: Name `VAULT_SECRET_ID`, Value — второе значение → **Add secret**.

### 10.2. Runner на сервере

1. github.com → `think-infra` → **Settings** → слева **Actions** → **Runners** → **New self-hosted runner**.
2. Выберите **Linux**, Architecture **x64**.
3. На странице будут команды в разделе **Download** и **Configure**. Выполните их **на сервере по одной**,
   начиная с `mkdir actions-runner && cd actions-runner`.
4. В команде `./config.sh …` **допишите в конец** ` --labels dev` (для prod — ` --labels prod`).
   Пример: `./config.sh --url https://github.com/Think-Faster/think-infra --token ABC123 --labels dev`.
   На вопросы config.sh (группа, имя, рабочая папка) просто нажимайте Enter.
5. Вместо `./run.sh` из инструкции GitHub установите runner как службу, чтобы он работал всегда:

```bash
sudo ./svc.sh install $USER
```

```bash
sudo ./svc.sh start
```

6. Обновите страницу **Runners** в GitHub: runner должен быть в статусе **Idle** (зелёный).

### 10.3. Доступ сервисов (tf-bff, tf-auth, tf-funnel)

Для **каждого** репозитория сервиса повторите шаг 10.1, только:

- в репозитории сервиса (например `tf-bff`), а не `think-infra`;
- значения — из **блока этого сервиса** (шаг 8.3 Д), у каждого сервиса своя пара.

Что сделать в самих сервисах — в ТЗ [docs/vault-tz/](docs/vault-tz/README.md).

### 10.4. Проверить выкатку

github.com → `think-infra` → вкладка **Actions** → слева `deploy redis` → справа **Run workflow** →
Branch: `dev` → **Run workflow**. Через минуту-две должна появиться зелёная галочка ✅.

## 11. Что делать после перезагрузки сервера

После любой перезагрузки сервера (или перезапуска контейнера `vault`) **Vault запечатан**.
Пока он запечатан: сервисы не стартуют (ждут до 10 минут, пишут в лог «Vault недоступен»),
выкатки из GitHub падают.

### 11.1. Проверить

```bash
docker exec vault vault status
```

Строка `Sealed true` — запечатан, `Sealed false` — всё в порядке.

### 11.2. Распечатать

Откройте менеджер паролей, возьмите `Unseal Key 1`. В команде ниже замените `ВСТАВЬТЕ_КЛЮЧ` на значение ключа,
**кавычки оставьте**:

```bash
docker exec vault vault operator unseal 'ВСТАВЬТЕ_КЛЮЧ'
```

В ответе будет `Unseal Progress 1/2`. Повторите команду с `Unseal Key 2` — в ответе `Sealed false`.

Очистите историю команд (ключи в ней остались):

```bash
history -c
```

Сервисы, которые ждали Vault, запустятся сами в течение минуты.

## 13. Если что-то пошло не так

Найдите в таблице текст, похожий на вашу ошибку.

| Ошибка / что видите | Причина | Что делать |
|---|---|---|
| `permission denied while trying to connect to the Docker daemon` | пользователь не в группе docker | шаг 5.2 и **переподключиться** |
| `нет прав на /opt/tf.infra` | папка принадлежит другому пользователю | шаг 7.3 |
| `tar: … Cannot open: File exists` или `Cannot utime: Operation not permitted` | файлы в `TF_INFRA_DIR` созданы от root | `sudo chown -R $USER <TF_INFRA_DIR>` и запустить снова |
| `Vault запечатан (sealed)` / `Vault is sealed` | Vault перезапускался | раздел 11 |
| `Vault is already initialized` | Vault уже запускали раньше — ключи выданы тогда | найти те ключи в менеджере паролей. Если их нет — см. ниже «Ключи потеряны» |
| `'key' must be a valid hex or base64 string` | ключ скопирован с лишним | вставлять только значение после `Unseal Key 1: `, без пробелов и `< >`; в одинарных кавычках |
| `токен Vault недействителен или истёк` | токен неверный или отозван | заново `export VAULT_TOKEN='…'` с правильным личным токеном |
| `секрета … нет в Vault` | пароль ещё не создан | `scripts/secrets.sh init`, потом повторить |
| `DOMAIN не задан в stands/…` | не заполнен файл стенда | раздел 6, или запуск с `--skip web-server` |
| `Port 80 is already in use` | сертификата нет, а порт 80 занят (старый nginx или другая программа) | проверить `DOMAIN` в файле стенда; остановить то, что занимает порт 80 |
| Сертификат не выпускается (`Certbot failed…`) | DNS домена не указывает на сервер | шаг 6.3, подождать, запустить снова |
| Сайт: **502 Bad Gateway** | сервис за nginx не запущен или порт указан неверно | `docker ps` — есть ли `tf-auth` / `tf-bff` / `tf-front`; сверить `*_PORT` в файле стенда |
| В логе сервиса `RedisConnectionException … SocketClosed` / `NOAUTH` | сервис подключается к Redis без пароля | сервис должен брать пароль из Vault (ТЗ в `docs/vault-tz/`) |
| В логе сервиса `Vault недоступен, запечатан или неверный VAULT_ROLE_ID/VAULT_SECRET_ID` | Vault запечатан или в GitHub неверные значения | раздел 11; проверить секреты сервиса в GitHub (10.3) |
| Выкатка в GitHub висит `Waiting for a runner` | runner не запущен | раздел 10.2, на сервере `cd ~/actions-runner && sudo ./svc.sh status` |

### Нужен root-токен, а он отозван

Выпускается заново двумя ключами распечатывания. По очереди:

```bash
docker exec vault vault operator generate-root -init
```

В ответе запишите `OTP` и `Nonce`.

```bash
docker exec vault vault operator generate-root -nonce='<Nonce>' '<Unseal Key 1>'
```

```bash
docker exec vault vault operator generate-root -nonce='<Nonce>' '<Unseal Key 2>'
```

Вторая команда покажет `Encoded Token`:

```bash
docker exec vault vault operator generate-root -decode='<Encoded Token>' -otp='<OTP>'
```

Ответ — новый root-токен `hvs.…`. После работы отзовите его (12.7).

### Ключи потеряны

Прочитать старые пароли будет невозможно. Если Vault **новый и пароли в нём ещё не нужны**
(например, запуск только начался), его можно создать заново — **это удаляет всё содержимое Vault**:

```bash
docker rm -f vault && docker volume rm tf-vault-data
```

Затем снова `scripts/bootstrap-stand.sh <стенд>` — он выдаст новые ключи.
⚠️ На работающем стенде так делать нельзя: все программы потеряют доступ к паролям. Позовите администратора.

### Не помогло

Соберите и отправьте ответственному за инфраструктуру:

- команду, которую запускали, и **последние 30 строк** вывода;
- вывод `docker ps -a --format 'table {{.Names}}\t{{.Status}}'`.

⚠️ Перед отправкой **сотрите из текста** всё, что похоже на `hvs.…`, ключи распечатывания, `VAULT_SECRET_ID`,
пароли, а также заголовки `Cookie:` и `Authorization:`.

## 14. Чего делать нельзя

- ❌ **Удалять тома Docker**: `docker compose down -v`, `docker volume rm`, `docker volume prune`,
  `docker system prune --volumes`. В томах лежат база данных, сообщения, Vault. Удалил — потерял данные.
- ❌ Отправлять ключи, токены и пароли в чат, почту, задачи, коммиты, скриншоты.
- ❌ Вписывать пароли в `stands/*.env`, `docker-compose.yml` и любые файлы репозитория.
- ❌ Делать `git pull` или править файлы в папке `TF_INFRA_DIR` — ею управляет выкатка.
  Код меняется только через GitHub.
- ❌ Перезапускать контейнер `vault` без необходимости — после этого его нужно распечатывать (раздел 11).
- ❌ Запускать `vault operator init` на работающем стенде — это для самого первого запуска, его делает скрипт.
